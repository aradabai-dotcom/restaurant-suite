# Gate V0.5 — dashboard restaurant

**Statut :** préparation documentaire uniquement après validation de la V0.4 simulation.  
**Aucune fonctionnalité V0.5 n’est implémentée dans le commit courant.**

## Objectif

Le dashboard V0.5 devra fournir une interface d’exploitation simple pour un restaurateur peu à l’aise avec WordPress, tout en restant plus légère et plus prévisible que l’empilement de plugins d’administration. Il devra administrer les données WooCommerce et les réglages Restaurant Suite sans créer de catalogue, de stock, de panier ou de commande parallèle.

## Contraintes non négociables

| Domaine | Exigence du gate |
|---|---|
| Source de vérité | Produits, variations, prix, stock, panier et commandes restent ceux de WooCommerce |
| Autorisations | Capacités WordPress dédiées, vérifiées côté serveur pour chaque mutation |
| Mutations | Actions explicites, nonce, validation serveur, journalisation sans PII |
| Commandes | Le dashboard devra lire et piloter WooCommerce ; aucune table de commande Restaurant Suite |
| Réglages | `crs_settings` versionné, numéro WhatsApp sensible jamais exporté dans les rapports |
| UX | Navigation courte, états vides, erreurs lisibles, responsive et accessible |
| Performance | Assets chargés par écran, rendu serveur prioritaire, JavaScript limité au comportement nécessaire |
| Sécurité | Aucun writer réel ne sera activé sans un gate séparé, des tests d’intégration et une autorisation explicite |

## Préconditions avant implémentation

Le prochain cycle devra commencer par un contrat de capacités et de transitions d’état, puis par des tests d’intégration WordPress/WooCommerce dans un environnement Docker/DDEV disponible. Il devra couvrir les rôles, la concurrence, les erreurs de permission, les réglages invalides, la journalisation et les régressions HPOS. Les tests navigateur et d’accessibilité devront être exécutés sur une instance dédiée avant tout déploiement.

Le dashboard ne devra pas transformer la V0.4 en writer réel par effet de bord. Tant que le writer WooCommerce et le parcours WhatsApp n’ont pas leur propre validation et leur propre décision de déploiement, ils resteront absents du runtime de simulation.

## Décision de sortie

La V0.5 pourra quitter le gate uniquement après revue du contrat, implémentation minimale par écran, contrôles locaux verts, tests DDEV/WordPress réels, audit d’autorisation et rapport public. Le présent document est une feuille de route de contrôle, pas une déclaration d’implémentation.
