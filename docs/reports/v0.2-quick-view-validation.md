# Rapport d’exécution — V0.2 Quick View

**Date :** 26 août 2026
**Statut :** implémentation locale validée ; déploiement staging à effectuer
**Dépendance :** V0.1 menu validée sur staging

## Périmètre implémenté

Le plugin ajoute un endpoint REST `GET /wp-json/crs/v1/quick-view/{product_id}` protégé par un nonce `crs_quickview`. Le serveur vérifie l’existence du produit, son statut publié et sa visibilité WooCommerce, puis construit un fragment HTML depuis les getters WooCommerce. Le fragment contient l’image, le nom, le prix, la description courte, la disponibilité, un lien vers la fiche produit et le formulaire natif WooCommerce d’ajout au panier lorsque le produit est achetable. Aucun prix fourni par le navigateur n’est utilisé comme source de vérité.

Le menu V0.1 ajoute un bouton « Aperçu rapide » par carte. Le bundle JavaScript est chargé uniquement lorsqu’un menu est rendu. Il crée une modale `role=dialog`, `aria-modal=true`, transfère le focus, verrouille le scroll, gère Échap, ferme sur le fond, restitue le focus au déclencheur et conserve un lien de repli vers la fiche produit. Le fragment est inséré dans un `template` DOM après une réponse REST same-origin ; le serveur échappe les valeurs et le formulaire est limité au HTML WooCommerce autorisé. Les événements `crs:quickview:open` et `crs:quickview:close` suivent le contrat existant.

## Fichiers principaux

Le service REST se trouve dans `plugin/restaurant-suite-core/src/QuickView/class-quickviewendpoint.php`. Le contrôleur navigateur source est `plugin/restaurant-suite-core/assets/src/quick-view.js`, son artefact est produit dans `assets/build/quick-view.js` et le CSS Quick View est ajouté à `assets/build/menu.css`. `MenuRenderer` expose les déclencheurs et localise l’URL REST, le nonce et les libellés. Les stubs versionnés permettent d’analyser les appels WordPress/WooCommerce/Elementor sans les embarquer dans la production.

## Limites et gate staging

Le package n’est pas déclaré pleinement validé avant son installation sur le WordPress staging. Il faut désactiver puis supprimer l’ancien package avant activation lorsque WordPress a installé chaque ZIP dans un dossier versionné, créer ou conserver les fixtures CRS existantes, appeler l’endpoint avec nonce et sans nonce, tester simple/hors stock/variable, vérifier le focus et Échap, simuler une erreur réseau, puis contrôler qu’Elementor reste compatible. Le test d’ajout au panier ne doit pas être transformé en commande réelle.
