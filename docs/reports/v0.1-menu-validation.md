# Rapport d’exécution — V0.1 menu

**Date :** 26 août 2026
**Statut :** implémentation déposée, validation locale verte, validation staging en cours
**Dépôt :** `aradabai-dotcom/restaurant-suite`

## Périmètre implémenté

V0.1 ajoute un menu WooCommerce rendu côté serveur à partir de `WC_Product_Query`. Le même `MenuRenderer` est appelé par le shortcode `[crs_menu]`, le bloc dynamique `restaurant-suite/menu` et le widget Elementor conditionnel. Les cartes affichent image, nom, description courte, prix WooCommerce, lien fiche produit et un état d’indisponibilité. Les produits variables renvoient vers leur fiche pour choisir une variation ; les produits simples achetables exposent un lien d’ajout au panier WooCommerce. Une catégorie vide produit un état propre, sans table catalogue parallèle.

Les arguments sont normalisés avec des bornes pour catégorie, pagination, colonnes, tri et ordre. Les styles sont préfixés `crs-`, responsive mobile et chargés uniquement au moment du rendu du menu. Le fonctionnement du menu ne dépend pas de JavaScript ; le shortcode et les liens restent accessibles lorsque JavaScript est désactivé. Elementor reste optionnel et ne stocke aucun produit.

## Fichiers principaux

`plugin/restaurant-suite-core/src/Menu/class-menuarguments.php` normalise les entrées ; `class-menuquery.php` construit la requête WooCommerce ; `class-menurenderer.php` rend les cartes ; `class-menucontroller.php` enregistre shortcode, bloc et widget ; `src/Blocks/menu/block.json` décrit le bloc ; `src/Integrations/class-elementormenuwidget.php` fournit l’intégration Elementor ; `assets/build/menu.css` contient les styles ; les tests unitaires couvrent les bornes, catégories, pagination et absence de stockage parallèle.

## Limites et décision de passage

La validation V0.1 ne sera déclarée complète qu’après installation du package sur le staging, création de fixtures synthétiques, contrôle du rendu simple/hors stock/variable/catégorie vide, vérification Elementor actif puis désactivé, test mobile et test sans JavaScript. Docker/DDEV demeurent indisponibles dans la sandbox ; cette limitation sera explicitement conservée dans le gate.
