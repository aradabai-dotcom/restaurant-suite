# Validation V0.4 — simulation stricte

**Date :** 27 août 2026  
**Périmètre :** build `0.4.0` de Restaurant Suite Core, déployée sur le staging autorisé.  
**Décision de sécurité :** aucune création de commande, aucun paiement, aucune décrémentation de stock et aucune ouverture ou émission WhatsApp.

## Résumé exécutif

La V0.4 ajoute une route REST et un formulaire de simulation clairement séparés de tout writer de commande. La build locale est validée par les contrôles PHP, JavaScript, contrats et packaging. Le staging a reçu la version `0.4.0` avec une seule copie du Core active après désactivation de la copie V0.3 précédente.

Le staging conserve volontairement les réglages par défaut désactivés. Le test REST réel a donc produit le refus attendu `service_disabled`, sans commande et sans message externe. Cette décision permet de valider la chaîne de sécurité et le rendu sans introduire de numéro WhatsApp, de réglage commercial ou d’action irréversible.

## Implémentation validée

| Élément | Résultat |
|---|---|
| Endpoint | `POST crs/v1/order/simulate`, enregistré pendant `rest_api_init` |
| Authentification | nonce REST standard `wp_rest` |
| Source catalogue/panier | WooCommerce uniquement |
| Champs de prix côté navigateur | Rejetés ; les montants sont server-owned |
| Panier vide ou snapshot invalide | Rejeté |
| Idempotence | Réutilisation même contexte ; conflit si contexte différent |
| Writer de commande | Absent du parcours de simulation |
| WhatsApp | Aucun numéro configuré ; aucun lien ouvert ou message envoyé |
| UI | Shortcode `[crs_order_simulation]`, formulaire rendu serveur et bundle léger |
| Événement navigateur | `crs:order:simulated` uniquement après acceptation |

## Contrôles locaux réellement exécutés

Les commandes suivantes ont été exécutées avec succès dans le dépôt :

```text
pnpm run build
composer dump-autoload --no-interaction
make validate
git diff --check
make package
```

Le résultat local final est le suivant : **33 fichiers** vérifiés par Parallel Lint, **17 fichiers** PHPCS, PHPStan niveau 6 sans erreur avec son avertissement informatif de version ancienne, **40 tests PHPUnit et 127 assertions**, validation des contrats JSON, build, ESLint, Stylelint, Vitest et diff check verts. Le package produit `dist/restaurant-suite-core-0.4.0.zip` et exclut les tests ainsi que les sources frontend non compilées conformément au script de release.

## Observations staging

La page synthétique de validation a affiché le formulaire avec les labels `Nom`, `Téléphone`, `Mode de retrait`, `Adresse` et `Note`, ainsi que l’avertissement explicite : « Aucune commande, modification de stock, paiement ou message ne sera envoyé. » Le produit synthétique WooCommerce a été ajouté au panier uniquement pour exercer la lecture du snapshot, puis retiré via le Cart Drawer. Après rechargement, le panier rendu côté serveur et le compteur étaient à zéro.

Un appel REST avec des valeurs synthétiques a répondu HTTP 422 avec `decision=rejected`, `code=validation_failed` et l’erreur métier `service_disabled`. Le résultat est conforme au choix de conserver `crs_settings` désactivé sur staging. Aucune commande n’est apparue dans l’écran WooCommerce après ce test, qui est resté vide.

La liste des extensions a confirmé que la version `0.4.0` était active et que l’ancienne copie `0.3.0` était inactive. Les copies historiques sont restées inactives et n’ont pas été supprimées afin de préserver un rollback manuel.

## Limites et non-affirmations

La simulation acceptée a été couverte localement avec un snapshot WooCommerce synthétique, mais **pas exécutée sur staging**, car les réglages staging sont volontairement désactivés et aucun numéro WhatsApp, même fictif, n’a été configuré. La Definition of Done complète du CDC V0.4 — création réelle d’une commande WooCommerce et lien WhatsApp relançable — n’est donc pas remplie et reste explicitement hors périmètre.

Docker/DDEV, HPOS, Playwright E2E complet, tests d’intégration WordPress, charge k6 et ZAP ne sont pas revendiqués. Le formulaire staging créé pour la validation est une page de test non commerciale ; il devra être retiré ou passé en brouillon avant toute utilisation publique du site.

## Conclusion

**Verdict : V0.4 simulation validée dans le périmètre autorisé.** Le gate strict a empêché toute écriture de commande, tout changement de stock, tout paiement et toute communication WhatsApp. La prochaine étape est la publication Git de cette itération et la préparation documentaire du gate V0.5, sans activer le writer réel.
